# Booking button integration

The deployed portfolio is plain HTML, CSS, and JavaScript. It has no React, Tailwind, TypeScript build, or existing component directory. The live booking anchor in `index.html` reproduces the supplied expanding orange circle, SVG corner decoration, and gradient using `meetings.css`. It works without JavaScript, keeps the booking URL, and supports keyboard focus and reduced motion.

The reusable React source lives at `/components/ui/button-hover.tsx`, with `/components/ui/button.tsx`, `/components/ui/demo.tsx`, and `/lib/utils.ts`. These are optional sources and are not loaded by the static page. The supplied button was adapted to use an anchor via Radix Slot, retain its real label, expand fully across the longer booking label, and show the effect on keyboard focus.

## React / TypeScript / Tailwind / shadcn setup

Use a separate React workspace when adopting these optional components; do not run the scaffold over the existing static portfolio:

```sh
npm create vite@latest portfolio-react -- --template react-ts
cd portfolio-react
npm install
npm install tailwindcss @tailwindcss/vite
npm install -D @types/node
npm install @radix-ui/react-slot class-variance-authority clsx tailwind-merge
```

In `vite.config.ts`, retain the React plugin, add Tailwind, and resolve `@` to the workspace root for the root-level component files supplied here:

```ts
import { fileURLToPath, URL } from "node:url"
import { defineConfig } from "vite"
import react from "@vitejs/plugin-react"
import tailwindcss from "@tailwindcss/vite"

export default defineConfig({
  plugins: [react(), tailwindcss()],
  resolve: { alias: { "@": fileURLToPath(new URL(".", import.meta.url)) } },
})
```

Add `"baseUrl": "."` and `"paths": { "@/*": ["./*"] }` to compilerOptions in both `tsconfig.json` and `tsconfig.app.json`. In `tsconfig.app.json`, include `["src", "components", "lib"]`.

Replace the starter CSS in `src/index.css` with `@import "tailwindcss";` and keep it imported by `src/main.tsx`. Then initialize shadcn:

```sh
npx shadcn@latest init
```

Point shadcn's CSS setting at `src/index.css` and configure its component aliases as `@/components`, `@/components/ui`, and `@/lib/utils`. Keep the theme variables generated by the CLI. Copy the supplied `components/` and `lib/` directories into this workspace after initialization.

Creating `/components/ui` keeps reusable UI primitives together and makes the supplied imports resolve consistently. If you prefer the common `src/components/ui` layout, move both directories under `src/` and change `@` in Vite and TypeScript to resolve to `src/`.

Render `<DemoOne />` from `@/components/ui/demo` in `src/App.tsx`, then run `npm run dev` or `npm run build`.

No npm dependencies are required by, or installed into, the current static portfolio. The commands above install the optional React component's dependencies when adopting it.

Sources: [shadcn Vite setup](https://ui.shadcn.com/docs/installation/vite), [Tailwind Vite setup](https://tailwindcss.com/docs/installation/using-vite).
